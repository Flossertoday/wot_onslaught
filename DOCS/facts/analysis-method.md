# 对局探索与异常判断方法

项目统一将 Onslaught/Comp7 称为“天梯”。

天梯模式没有平局；GUI 的胜负计数只显示“胜 / 负”，总览也仅显示胜场与负场。

## 当前估计情景（2026-10-01）

你规定：所有没有最终战报的对局，一律假设为提前离场，预计胜率按 **30%** 计算。
该规则同时覆盖历史、新增和未调查的录像，不再以阵亡观测或历史调查记录作为估计资格。
估计胜率 = `(已知胜场 + 无最终战报场数 × 0.30) / 总场数`。
这是期望值计算，不将预计胜场取整为实际胜场，也不改写任何逐场未知结果。

GUI 同时保留已知胜率、原始胜负计数、总览中的未知数量及缺失上下界。
分组和筛选后的情景估计统一将其包含的无最终战报录像按 30% 计算；
这个统一分配是假设，不能由总体估计推导为各地图真实胜率。
数据资格以 `result=unknown` 且 `result_status=no_result_block` 判定。
已有最终战报但身份、队伍、解析等验证异常的对局不属于无战报；含这类未知的组仍不显示单点估计。
“假设提前离场”与实际调查证据分开显示，不把假设写成已确认阵亡或已调查。
声望与积分缺失仍不补估。

历史 2026-09-30 冻结样本的 78 场按此规则计算仍为
`(158+78×0.30)/369=49.1599%`，显示为 **49.2%**。

本文件记录当前方向。目标是让你自主选择标签、观察差异、追到单场，不是自动输出一串
“显著”的组合。地图单标签已能指引复盘，不应为了建模复杂度而降低它的优先级。

## 一条交互链

**选择结果指标 → 筛选研究范围 → 选择一个或多个分组标签 → 比较分组 → 查看组内对局 → 检查单场证据。**

积分变化、声望和胜率是三个并列的结果指标。积分变化直接记录实际加减分，作为 GUI
默认结果；声望用于更细地比较表现。它们不能仅作为胜率分析中的分组标签或附加列。
切换结果指标时保留分组、日期、多值筛选和最低样本设置，更新总览、表格与排序口径。

- 积分视图：场均积分变化、已记录积分合计、中位数、中间 50% 对局、胜局平均加分、
  负局平均扣分；声望视图：均值、中位数、中间 50%、胜局/负局平均声望。
- 每个指标按各自有值场次统计，真实 0 保留，缺失不填 0；总场数始终保留。
  最低样本阈值对应当前指标的有值数。胜负拆分也只包含对应指标有值的对局。
- 所有结果视图的分组表显示本人“平均声望”和“平均输出”，替代差值与缺失/未知列。
  平均输出指 `damageDealt`，不含协助伤害；两项分别以组内对应字段有值场次为分母，
  不要求该场积分有值。无有值样本显示“—”；悬停展示各自有值场数。
- 中间 50% 是有值样本第 25 和 75 百分位，使用排序后 `(n−1)×p` 位置线性插值。
  它描述逐场分布，不是均值的置信区间，也不修正缺失偏差。
- 每种结果都支持均值/胜率升降序，缺失组始终排最后；不能按胜率排序却显示为积分排序。
- 30% 情景、Wilson 区间和未知胜率上下界只属于胜率视图，不迁移成积分或声望估值。
  旧版保存的研究视图恢复为胜率视图，新保存的视图包含结果指标。

筛选与分组是不同操作：例如先限定重坦，再按地图×出生方分组；也可以只按地图分组，
筛选某种局型。各组指标以当前筛选范围中的组内对局计算，显示的是描述性统计。

伤害区间按本人 `damageDealt` 划分为 `<2000`、`2000–2999`（2000≤输出<3000）、
`3000–4000`（含 3000 和 4000）、`>4000`；缺失仍为“未知”。三个结果视图、
筛选和组内对局共用此标签。恢复旧保存视图时，含 `2000–3999` 或 `≥4000` 的
伤害筛选整项移除并提示重新选择，避免悄悄改变边界或显示空样本；分组和其他筛选保留。

## 局型口径（2026-10-01）

原来的本人分段、六名队友分段构成、七名对手分段构成、队友黄金及以上人数、
对手黄金及以上人数五个菜单项合并为一个“局型”，用于分组和多选筛选。
房间指双方全部 14 人，含本人。分类前直接跳过定级赛玩家，其分段不参与
勇士/传说存在判断，也不参与黄金、白银和青铜人数统计。白银和青铜合计
计数，不包含黑铁。采用以下人数门槛：

- 高压局：有勇士或传说，黄金、勇士和传说合计 ≥10。
- 低压局：白银和青铜合计 ≥10，不包含黑铁。
- 黄金局：无勇士或传说，黄金人数 ≥8。
- 其它：其余情况。

四类互斥且覆盖所有分段可读取的房间；全部玩家均为定级赛
时，跳过后按兜底规则归为“其它”。原始名单不足 14 人或非定级玩家分段缺失的
为“未知”，这是数据不可观测，不是规则缺口；不能把无战报场当成低压局。
编码沿用 `comp7Rank`：1 传说、2 勇士、3 黄金、4 白银、5 青铜、6 黑铁。
单场战报仍展示每名玩家的原分段。

恢复旧保存视图时，旧分段分组改为局型并去重；旧分段筛选，以及含旧“白银局 /
未分类”值的局型筛选移除并显示提示，要求重新选择局型筛选。旧类别与新类别
不是一一对应，不能直接替换为低压局。其他分组、筛选和结果指标保留。

首次范围默认七天。扩大到旧录像是显式操作。界面必须显示截止时间和样本量；改变筛选
不能悄悄把无战报的比赛从总场数分母中消失。

## 每个分组同时回答三个问题

1. **观察到了什么？** 总场数、已知胜负、完整战报胜率和表现分布。
2. **未知会改变多少？** 未知比例，以及 `[wins/total, (wins+unknown)/total]`。
3. **小样本有多不稳定？** 已知胜率的 Wilson 区间、已知场数、小样本提示。

第 2 项是缺失结果的确定性上下界，第 3 项是以已知样本为基础的抽样不确定性。
两者不能混为一个“置信度”；Wilson 区间不会消除提前离场造成的选择偏差。

若某组上界低于其余对局下界，标记为“在这批样本里，对未知取值稳健的低胜率”。
不要称为总体显著异常，更不应称为地图或车型造成了失败。

## 标签与时间关系

- 赛前：地图、出生队伍、实际车辆、双方战前分段、组队（核验后）。
- 时间：日期、后续可增加当天第几场和连续作战时长，需先明确会话间隔规则。
- 战后：伤害、生存、技能使用、声望和结果，用于描述与复盘。
- 观测质量：战报是否存在、是否记录到赛后、是否观测到本人阵亡。

不要将战后标签当成赛前混杂因素一股脑加入“地图影响”回归。未知的队友分段不能用
当前账号分段或前后场插值替代。只知道分段区间时，不假装知道精确匹配积分。

## 探索与确认分开

探索允许多种组合，可用最低场数过滤和排序找值得复盘的组；不以 p<0.05 为是否看录像
的门槛，也不对每次随意改筛选都显示“显著”。极端的 0/3、3/3 应保留可见但突出样本量。

确认阶段再冻结：待比较组合、实际有意义的差值（例如 10 个百分点）、时间窗口、主指标、
比较家族及缺失处理。首选在后续新对局验证，而不是用同一批数据发现后又宣布验证。
若同一批做多项正式检验，记录比较家族并校正；自适应探索历史仍不能被简单 BH 完全抵消。

数据增多后考虑分层二项/逻辑回归，以部分汇总处理稀疏地图×车辆×出生方，并检查
日期、分段、选车混杂与连续作战相关性。只在某图用某车时，必须允许“无法区分图与车”。
现有窗口只有少数作战日，不把按日重采样当作万能可靠区间。

## 缺失机制改变后的优先级

2026-09-30 实测：78 场未知全部在本人阵亡后、结算前结束录制。这违反简单随机缺失假设。

当前优先使用边界/情景分析和单场复盘，不拟合一个模型把所有未知结果当事实填上。
完整战报中阵亡后的获胜比例只能作为对照信息，不能无条件推广给提前离场的比赛。
若将来研究插补或观测概率加权，必须单独列出可识别性假设，并同时保留不插补结果。

长期最有价值的补充是独立记录收到的最终战报，让每场结果不依赖是否留在战场。
实现前验证当前客户端是否在离场后实际收到该场结果、可用关联 ID 和持久化时机；
不能假设读取缺失录像能恢复录像结束以后发生的事情。
