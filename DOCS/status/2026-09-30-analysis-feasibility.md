# Replay 分析实测与技术路径 — 2026-09-30

## 结论

目标中的多数标签已能离线提取。采用 **JSON 战报为主、当前客户端配置解释标签、
二进制检查完整性** 的路线；目前没有必要实现完整游戏仿真或逐场播放/OCR。

主要约束是 **21.1% 的近期录像未记录最终结算**。应先带缺失边界分析，再决定是否
针对少量重点录像深挖事件或人工复盘。此次不把未知补成失败，也不将初步低胜率当作确定异常。

## 二进制验证

近期 369 场全部成功解密、解压和遍历完整包边界，无失败；未执行任何 pickle。

| JSON 结果 | 场数 | 记录赛后阶段 | 含 0x11 结算候选包 |
| --- | ---: | ---: | ---: |
| 未知 | 78 | 0 | 0 |
| 胜利 | 158 | 158 | 158 |
| 失败 | 133 | 133 | 133 |

78 场未知录像的阶段值全部停在 1→2→3。当前客户端 ARENA_PERIOD 明确
3=BATTLE、4=AFTERBATTLE。291 场完整录像由阶段 3 到 4 计算的时长，与
JSON duration 的差在 −0.071 到 +1.041 秒之间，支持包阶段解释。

这说明目前的缺口不是简单漏读第二块 JSON。**没有证据支持能从这 78 场现有录像
直接恢复最终战报**；但本次没有完整解释所有战斗事件，也不宣称任何间接恢复都绝对不可能。
没有观察到完整结算前，不根据录像结束时的局势猜胜负。

格式实现参考：[容器与解密参考](https://github.com/Monstrofil/replays_unpack/blob/master/replay_unpack/replay_reader.py)、
[包边界参考](https://intelliagent.gitlab.io/wotto-wiki/format/packet-stream/)、
[0x11 的探索性定义](https://intelliagent.gitlab.io/wotto-wiki/packets/packet11/)。
实际兼容性由本地 369 场验证，而非仅依据参考项目声称的版本支持。

锡默尔斯多夫最值得看原始复盘：已知胜率最低，但 Wilson 95% 区间仍为
11.7%—54.6%，且 30% 结果缺失。其单侧 Fisher p≈0.0437，经 22 张地图 BH
校正后 q≈0.9622；**本轮没有地图达到校正后 q<0.05**。这不是证明所有地图都一样，
而是目前样本不足以确认异常。

荒蛮之地夜间只有一场未知，即使那场是胜利，样本胜率仍不超过 41.2%。因此它的
“这批录像表现偏低”对缺失处理更稳健，可以与锡默尔斯多夫并列优先复盘；仍不是显著性结论。

组合标签的实际可用性也已测试：

- 队友 6 人与对手 7 人的分段列表已加入每场记录；未将类别强行转为精确积分，也未做高维组合扫描。

## 据此决定的后续步骤

1. 保留本次轻量工具和 CSV 证据。当前只有几百场，不必先搭数据库服务、UI 或完整事件解码器。
2. 先用地图×出生方、地图×车型及双方段位分布复盘上述两张地图；选代表性胜负局，
   比较表现指标，而不是把伤害等战后变量当作赛前原因。
3. 补数据优先于扩大统计模型：核实未来能否保留完整战斗到结算，或另行保存本人的战报。
   未经另行任务不改客户端设置、不装记录模组；当前没有部署任何游戏修改。
4. 如果进一步调查缺失录像，只对明确问题做事件解析，并先以已知结局录像作对照验证。
   不承诺能找回录像停止后发生的事件。
5. 新数据足够后再做分层胜率模型，考虑选车、出生方、本人分段和时间，并以前向新对局
   验证异常组合。目前不靠模型掩盖 78 场结果缺失。
