# 78 场未知结果的原因与 GUI 首版

## 原因调查

沿用首轮冻结的七天窗口，共 369 场。78 场未知录像**全部符合本人阵亡后、最终结算前
结束录制的模式**，不是把“负场”写成了未知。你在本次调查中确认经常阵亡后返回车库
并开始下一场；结合下面的证据，这最有力地支持了主动提前离场是主要原因。

| 证据 | 78 场未知 |
| --- | ---: |
| 本人的生命值更新降至 0 或以下 | 78 |
| 进入 lookAtKiller 视角 | 78 |
| 进入 postmortem 观战视角 | 77 |
| 以完整终止标记结束、包边界正常 | 78 |
| 出现 AFTERBATTLE 阶段 / 0x11 结算候选包 | 0 / 0 |
| 阵亡到录制结束 | 最短 3.3 秒；中位 17.5 秒；最长 125.6 秒 |
| 录制结束到下一场开始 | 中位约 57.5 秒 |
| 两分钟内开始下一场 | 74 |

唯一未进入 postmortem 的录像是 2026-09-27 18:11 阿拉曼机场 268 工程；
阵亡约 3.3 秒就结束，仍有 lookAtKiller。另四场下一局间隔约 159、205、1063、184 秒，
并没有因此推断别的故障。

没有观察到文件截断或结构损坏。终止标记只证明录制流正常收尾，不证明具体按下了哪颗
退出按钮，也不能单独区分主动离场和某些正常收尾的断线情形。本次没有解码退出按钮事件。

## 如何验证，而不是只看字段名

当前 `Vehicle.def` 的 `onHealthChanged` 参数是
`INT16, INT16, OBJECT_ID, UINT8, INT8`，对应 10 字节 payload。
按本人车辆 ID 匹配 `0x08 / method 0x04`，排除其他车辆阵亡造成的误判。

以 291 场已知战报作对照：

- 是否阵亡：**291/291** 与战报一致。
- 153 场阵亡对局中，事件时间减去战斗阶段起点，与战报 lifeTime 的差为
  −0.071 到 +1.095 秒，中位差约 0.47 秒。
- 最后观测血量仅 260 场与最终战报相同，另 10 场没有该类血量更新；其余 21 场不一致。
  因此本次验证支持的是**阵亡识别**，不把这些数据包装成已验证的完整血量轨迹。

格式线索来自 [健康更新结构参考](https://intelliagent.gitlab.io/wotto-wiki/packets/packet08/subtype04/)，
兼容性由当前客户端声明和 291 场对照验证。未执行二进制流中的 pickle 或游戏代码。

## 能否找回结果

检查了两处缓存：

1. 项目 `ReplayCache.db`：此前确认这 78 场也是未知，不能补齐。
2. 当前客户端 `APPDATA/Wargaming.net/WorldOfTanks/battle_results`：现存 55 份，
   50 份按 arena ID 对应已有完整猛攻战报，另外 5 份 `bonusType=1`，是普通战斗。
   没有找到缺失的猛攻结果。

独立战报缓存使用受限反序列化，只允许原始容器及 set/frozenset，禁止其他全局调用
和 persistent ID；按 50 个已知战报共同验证了时间、模式、胜方和时长的数组位置，
没有直接套旧版协议。缓存只读，原始缓存内容未复制进项目。

当前不能把这 78 场最终结果补成可靠事实。后续应研究独立保存**每场实际收到的最终战报**，
使未来数据不依赖是否一直留在战场。当前没有安装模组、改变游戏设置或要求改变打法。

## 对统计的影响

缺失明显与阵亡和离场有关，不是随机抽掉 21.1% 的比赛：

- 完整战报中的阵亡对局：34 胜 / 153 场，22.2%。
- 完整战报中的存活对局：124 胜 / 138 场，89.9%。
- 未知结果的 78 场全部有阵亡证据。

这些数值说明完整战报的 54.3% 不能直接当成这 369 场的真实胜率；但也**不能用 22.2%
乘以 78 来填补胜场**，因为离场时间、局势、选车等仍可能影响未知组的结局。

地图单标签依然给出了有用信息。荒蛮之地夜间 6 胜 10 负 1 未知：

- 对它最有利：未知算胜，胜率上界为 7/17 = 41.2%。
- 对其余地图最不利：其余未知全部算负，胜率下界为 152/352 = 43.2%。
- 因此无论 78 场未知如何分配胜负，**这批样本中荒蛮之地夜间仍低于其余地图**。
  这是对缺失结果取值稳健的样本描述，不是对长期水平的显著性结论。

后续方法见 [分析方法](../facts/analysis-method.md)。

## GUI 首版

启动后访问 `http://127.0.0.1:8765/`。在开发工作树双击 `Start-Explorer.cmd`，
或执行 `python tools/explorer/server.py --open-browser`。只绑定本机回环地址。

- 16 种标签可以自由选择并组合分组，日期与多值筛选可叠加；同一条件内为“或”，不同条件间为“且”。
- 默认仍是最近七天、按地图研究；保留单标签的直接价值。
- 研究标签包括地图、出生队伍、坦克/类别、本人/双方分段构成、黄金以上人数、日期、
  战后表现及录制完整性。队友分段明确排除本人，定级赛单列。
- 分组显示总场数/已知、胜负平、Wilson 区间、未知比例、未知上下界以及相对其余样本差值。
- 显示“本组上界仍低于其余下界”的稳健样本线索；不在自由探索中反复报显著性。
- 点击分组 → 对局列表 → 单场详情；查看双方 14 人的分段与伤害、本人表现、录像内阵亡/观战/结束时间。
- 结果未知时数值保留缺失，绝不显示成 0。原始录像可复制路径或下载；不会自动启动游戏。
- 可在本地浏览器保存/恢复一份研究视图；窄屏时筛选可折叠。

CSV 仅是现有提取流程的中间存储，**不再作为交互分析工具**。GUI 通过本地只读 API 获得
规范化数据。本版是固定快照，不会自动扫描新录像，不含嵌入式视频播放或高维调整模型。
