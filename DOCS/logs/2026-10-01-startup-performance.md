# 启动性能 — 2026-10-01

开发分支：`codex/startup-performance`，独立工作树基于 `main` 的 `56b809e`。

## 瓶颈与改动

实际样本为 500 场录像、5530 条玩家记录。原重复启动的 Python 导入约 0.27 秒，
同步约 7.13 秒，分析约 10.51 秒；约 18 秒后才能开始提供页面。
第一次在开发工作树补齐 69 场录像的同步为 14.42 秒，未将复制成本混入重复启动基线。

- 原同步解析完整战报，并计算源/目标两个 SHA-256；改为只解析模式/地图头和逐块比较完整文件。
  同名文件仍逐字节验证，冲突不覆盖，新复制文件仍完整验证 JSON 区。
- GUI 使用 `audit.py --data-only`，跳过不使用的三份统计 CSV 及 SciPy。
  原审计 cProfile 中统计汇总及导入约占 4.08 秒。独立审计默认行为保持完整。
- 保存可丢弃的 GUI 快照，复用前校验全部录像和相关输入内容。
  日期窗口及结果计数每次重算；依赖变化、录像增删修改、缓存损坏时重建。
  缓存发布采用原子替换，提取与当前文件内容不一致时不保存。

## 验证

- 26 项 Explorer 和 24 项分析 Python 测试通过；前端语法、30% 情景及结果视图检查通过。
- 新回归覆盖同大小同修改时间的内容变化、事件流最后一字节冲突、残缺战报拒绝发布，
  以及录像增删、代码/证据/游戏缓存/游戏定义变化、日期窗口边界、缓存损坏和写入失败。
- 实际缓存 JSON 与固定同一截止时间的完整审计 JSON 完全相同，包括 500 场及全部 5530 条玩家记录。
- 启动真实 HTTP 服务，在无 GUI 缓存时就绪约 11.86 秒，复用缓存时约 5.54 秒；
  完整 API 下载完成分别约 12.09 / 5.78 秒。两次 API 均与完整审计相同，
  录像下载字节与归档文件及 SHA-256 相符。以上不包含浏览器进程启动和页面渲染。
- 原历史提取证据保持原样。实际同步的 69 场录像留在工作树本地，不包含在代码提交中。

## 剩余成本

重复启动仍读取源/归档文件和 SHA-256 校验本地录像，因此不保证瞬时启动。
任一分析输入变化会全量重建；尚未实现逐场增量提取或后台刷新。
新数据和首次启动大约 12 秒，当前优化主要收益在数据未变化的重复启动。
分支未合并至 `main`；主工作树原有 69 场未跟踪录像保留。
